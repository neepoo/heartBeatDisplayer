# BLE 实机验证

这些检查需要目标平台的真实电脑、支持 BLE 的蓝牙适配器，以及一块可广播心率的 Garmin Forerunner 255。Windows 10 2004+、macOS 14+、Ubuntu 24.04 x64 X11 分别验收，自动化模拟检查不能替代这些硬件检查。

当前 macOS/Linux 预览版尚未完成下列实机验收，清单中的内容是测试步骤，不是通过记录。

## 准备手表

1. 戴好手表，确认光学心率传感器正在显示读数。
2. 在手表的腕式心率设置中开启“广播心率”。如果只对活动广播，请先开始一项活动。
3. 本应用通过附近广播发现设备并连接标准 GATT 心率服务，不需要预先在系统设置中配对手表。Mac 需要同意蓝牙访问权限，Linux 需要运行中的 BlueZ 系统服务。

## 正常流程

1. 启动应用并扫描，等待扫描完成；设备列表应出现手表名称或匿名心率设备。各平台名称和标识格式可能不同，macOS 不使用 MAC 地址，不通过名称推定是同一设备。
2. 选择手表并连接。确认界面开始更新 BPM，静置和短暂活动时数值变化合理。
3. 在常玩的无边框游戏中保持连接至少 30 分钟，确认持续收到数据，没有重复的断开提示或 UI 卡顿；锁定后鼠标穿透，显示/隐藏均不抢焦点。
4. 关闭应用，确认进程很快退出；重复启动、扫描、连接三次，确认没有遗留连接阻止下一次连接。

## 故障与恢复

1. 扫描前关闭系统蓝牙，应显示可操作的中文提示；重新开启后扫描应恢复。
2. 扫描进行中取消操作，应立即停止扫描，且下一次扫描仍可使用。
3. 连接后关闭手表的心率广播、让手表离开范围，或关闭系统蓝牙，应触发断开状态；控制器应按其重连策略处理。
4. 在连接或启用通知过程中取消，待系统操作结束后应释放本应用持有的资源；随后重新扫描连接应成功。迟到通知不得更新已切换的会话。
5. 关闭手表广播后尝试连接只带 Garmin 名称的广播，错误应明确指出缺少 0x180D/0x2A37 或 Notify，并提示开启心率广播。
6. 如果电脑没有 BLE 适配器、适配器被设备管理器禁用或被硬件开关关闭，分别确认提示能够指出对应处理方式。
7. 扫描并保存手表后退出应用，重启电脑，再让手表保持广播并启动应用。Windows 需要覆盖无系统发现缓存的重连；macOS/Linux 需要覆盖设备标识失效的提示。附近同名 Garmin 设备不能被误连接；无法恢复旧设备时应要求重新扫描选择，不按名称自动替换。

## 新平台专用检查

- Mac：首次允许／拒绝蓝牙权限、系统设置重新允许、广播暂停、电脑睡眠／唤醒；分别验证 Intel 和 Apple Silicon 包。
- Mac：置顶、锁定穿透、显示／隐藏不抢焦点；另记录解锁点击、拖动和缩放时前台应用是否改变。窗口禁止成为 key/main 的原生属性检查不能代替实际应用激活行为测试。
- Linux：普通用户扫描连接、适配器关闭／rfkill、BlueZ 服务重启、断线期间退出；不要使用 root 来掩盖权限问题。
- Linux X11：验证置顶、完整鼠标穿透、解锁恢复、CapsLock／NumLock 状态下快捷键、托盘缺失时仍能打开设置和退出。Wayland 只检查明确的能力限制提示，不记为完整悬浮通过。
- 三端：启动 `--demo` 不请求蓝牙权限、不初始化适配器；切换到真实连接才接入系统蓝牙。

## 记录结果

记录操作系统版本与架构（Linux 另记录桌面和 X11/Wayland）、蓝牙适配器型号及驱动版本、手表固件版本、首次连接耗时、持续运行时间，以及每个故障场景的实际提示。若连接失败，记录设置窗口中的 GATT 错误；不要将真实设备 ID、扫描结果或心率数据提交到公开仓库。

目标：程序收到有效通知到更新数字不超过 500 毫秒；该延迟不包含手表本身的测量和广播延迟。对照调试器通知时间和 UI 更新记录测量，不能仅凭手表表盘和电脑的数字差异推算。

多屏：分别以 100%、150%、200% 缩放显示，跨屏拖动后重启，拔掉原显示器后重启，确认悬浮窗完整可见、字形与曲线清楚；使用重置位置可恢复到主屏右上角。
