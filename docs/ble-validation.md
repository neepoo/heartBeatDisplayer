# BLE 实机验证

这些检查需要 Windows 10 2004（19041）或更高版本、支持 BLE 的蓝牙适配器，以及一块可广播心率的 Garmin Forerunner 255。自动化测试不能替代这些硬件检查。

## 准备手表

1. 戴好手表，确认光学心率传感器正在显示读数。
2. 在手表的腕式心率设置中开启“广播心率”。如果只对活动广播，请先开始一项活动。
3. 不需要在 Windows 中配对手表；本应用通过附近广播发现设备并连接标准 GATT 心率服务。

## 正常流程

1. 启动应用并扫描。扫描约 8 秒；设备列表应出现 `Garmin`、`Forerunner`，或匿名心率广播的 `心率设备 (XX:XX:XX:XX:XX:XX)`。
2. 选择手表并连接。确认界面开始更新 BPM，静置和短暂活动时数值变化合理。
3. 在常玩的无边框游戏中保持连接至少 30 分钟，确认持续收到数据，没有重复的断开提示或 UI 卡顿；锁定后鼠标穿透，显示/隐藏均不抢焦点。
4. 关闭应用，确认进程很快退出；重复启动、扫描、连接三次，确认没有遗留连接阻止下一次连接。

## 故障与恢复

1. 扫描前关闭 Windows 蓝牙，应显示可操作的中文提示；重新开启后扫描应恢复。
2. 扫描进行中取消操作，应立即停止扫描，且下一次扫描仍可使用。
3. 连接后关闭手表的心率广播、让手表离开范围，或关闭 Windows 蓝牙，应触发断开状态；控制器应按其重连策略处理。
4. 在连接或启用通知过程中取消，等待该次 Windows GATT 调用自然完成后应释放设备；随后重新扫描连接应成功。
5. 关闭手表广播后尝试连接只带 Garmin 名称的广播，错误应明确指出缺少 0x180D/0x2A37 或 Notify，并提示开启心率广播。
6. 如果电脑没有 BLE 适配器、适配器被设备管理器禁用或被硬件开关关闭，分别确认提示能够指出对应处理方式。
7. 扫描并保存手表后退出应用，重启电脑以清空未配对设备的系统缓存，再让手表保持广播并启动应用。自动连接应先定向扫描、再连接同一蓝牙地址和地址类型；即使附近有同名 Garmin 设备，也不能改连另一台。若手表使用会轮换的随机地址，旧记录可能失效，此时应手动重新扫描并选择设备。

## 记录结果

记录 Windows 版本、蓝牙适配器型号及驱动版本、手表固件版本、扫描到的名称、首次连接耗时、持续运行时间，以及每个故障场景的实际提示。若连接失败，保存设置窗口中的 GATT 错误提示；开发时可通过调试器查看 Trace 输出。

目标：程序收到有效通知到更新数字不超过 500 毫秒；该延迟不包含手表本身的测量和广播延迟。对照调试器通知时间和 UI 更新记录测量，不能仅凭手表表盘和电脑的数字差异推算。

多屏：分别以 100%、150%、200% 缩放显示，跨屏拖动后重启，拔掉原显示器后重启，确认悬浮窗完整可见、字形与曲线清楚；使用重置位置可恢复到主屏右上角。
